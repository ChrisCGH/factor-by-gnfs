USER PROBLEM:
-------------
"With auto tuning enabled, fewer relations are generated, more slowly:
 150k in about 30 minutes, compared to 2.6 million in 45 minutes 
 without auto tuning"

NUMBERS:
--------
Without auto-tuning: 2,600,000 relations / 45 min = 963 rel/sec ✓ GOOD
With auto-tuning:      150,000 relations / 30 min =  83 rel/sec ✗ BAD

Performance loss: 91%

ROOT CAUSE IDENTIFIED:
----------------------
Lines 397 and 482 in gnfs/LatticeSiever.cpp used WRONG OPERATOR:

    cutoff -= adjustment;     ← WRONG! (subtraction)

Should have been:

    cutoff += adjustment;     ← CORRECT! (addition)

WHY THIS CAUSED 91% SLOWDOWN:
------------------------------
With WRONG operator (-=):
  1. Auto-tuning increases adjustment to improve performance
  2. Cutoff gets SMALLER (subtract more)
  3. Smaller cutoff → MORE candidates pass threshold check
  4. More candidates → MANY more polynomial evaluations
  5. More evaluations → MUCH SLOWER performance
  6. Auto-tuning detects slowdown, increases adjustment more
  7. Performance gets even worse
  8. DEATH SPIRAL: Performance craters to 83 rel/sec

With CORRECT operator (+=):
  1. Auto-tuning increases adjustment to improve performance
  2. Cutoff gets LARGER (add more)
  3. Larger cutoff → FEWER candidates pass threshold check
  4. Fewer candidates → Fewer polynomial evaluations
  5. Fewer evaluations → FASTER performance
  6. Auto-tuning finds optimal adjustment value
  7. HEALTHY OPTIMIZATION: Converges to ~1000 rel/sec

THE FIX:
--------
Changed 2 lines in gnfs/LatticeSiever.cpp:

  Line 397: cutoff -= adjustment; → cutoff += adjustment;
  Line 482: cutoff -= adjustment; → cutoff += adjustment;
